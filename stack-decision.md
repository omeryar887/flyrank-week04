# Week 4 — Stack Decision

## Decision

For the first portfolio version, I selected:

**HTML + CSS + Netlify**

## Options considered

### Option 1 — Plain HTML/CSS
Simple static files with no framework.

**Advantages**
- Easy to understand
- Fast to build
- No framework setup
- Easy to deploy
- Good fit for a content-focused portfolio

**Trade-off**
- More manual work if the site becomes highly interactive.

### Option 2 — React
A component-based frontend approach.

**Advantages**
- Reusable components
- Strong ecosystem
- Useful for more complex interfaces

**Trade-off**
- More setup than this initial portfolio milestone requires.

### Option 3 — Flutter Web
A framework I already use for application development.

**Advantages**
- Familiar development environment
- Reusable Flutter knowledge

**Trade-off**
- More infrastructure than needed for a simple portfolio site.

## Why I chose HTML/CSS

The immediate goal is to establish the portfolio online, not to introduce unnecessary technical complexity.

A static HTML/CSS site gives me a small, understandable foundation. I can add JavaScript or another tool later if a real requirement justifies it.

## Hosting decision

I selected Netlify for the initial deployment because the assignment specifically supports a simple static deployment workflow.

The project can be uploaded as a folder containing `index.html` at the root.

## Decision principle

I chose the smallest stack that can support the current requirement.

If the portfolio later needs functionality that plain HTML/CSS cannot handle cleanly, I can revisit the stack based on that actual requirement.
